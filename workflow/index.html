機台開發治理系統：從混亂到卓越

解決需求未凍結、規格無單一來源、軟硬體脫鉤等核心痛點。我們導入「研發」與「產品」的**雙軌流程 (Dual-Track Flow)**，在實驗自由度與量產穩定性之間取得完美平衡。

研究流程 (Research Flow)

  • • 適用：DEV / Lab Machine
  • • 特色：快、靈活修改、快速驗證
  • • 控管：輕量化 ECR，快速迭代

產品流程 (Product Flow)

  • • 適用：Platform / Customer Machine
  • • 特色：Freeze、高度重現、可追溯性
  • • 控管：嚴格階段閘門與 ECN 流程

    4 治理五大支柱

    機台身份管理

    拒絕孤兒機台。所有實體機必須具備 Machine ID、金屬銘牌、與對應的 Config 狀態紀錄。

    配置管理 (Config)

    禁止為單機 Fork 程式碼！透過 Config Table (JSON/XML) 讀取硬體特徵，由軟體主線自動載入對應模組。

    單一真實來源 (SSOT)

    BOM 在 ERP/PLM、圖面在受控庫、程式在 Git Tag、需求在 Jira。嚴禁私人 Excel 傳遞。

    變更控制 (Change)

    設計凍結後，任何變更必須發起 ECR。評估影響、庫存損耗與重新驗證需求，核准後轉 ECN。

    平台化戰略

    走向「樂高式」模組化。核心平台保持標準化，客製化僅侷限於外接模組的置換，降低維護成本。
